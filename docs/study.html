Study v1.3 implementation map

Experiment-Harness, harness version 0.3.0, branch study-v1.3, 2026-10-09. Specification section → module → test, the invariants, the provisional items, and what is still a placeholder.

Source of truth. docs/spec/SPEC_ANSWERS.md (the author's decisions, keyed to v1.3 section numbers), spec v1.0 and the implementation brief. The text of Experiment_Specification_v1_3.md and the 9 October experiment_notes.tex were not available when this was written; the details that only the v1.3 text fixes are filled in provisionally (marked provisional) and listed in section 5 and in PLAN.md section 10.

1. Pipeline

Stage 1  reproduce      all 79 CVEs, vulnerable + fixed, 10 clean runs each       -> reproduction.jsonl
Stage 2  generate       10 attempts x (A, B, C, X, Y, Z) per eligible CVE         -> attempts.jsonl (generation)
         classify       build once, screening run, 10 clean reruns               -> attempts.jsonl (classification)
Stage 4  select         one near-miss per (CVE, generator), seeded; twin order    -> selection.jsonl
Stage 3  sibling        author-written F, validated 10/10, rubric flagged         -> siblings.jsonl
Stage 5  review         e0 (+ Experiment B packets), crossed x x r x j schedule   -> inputs.jsonl, reviews.jsonl
         analyse-dev    thresholds, policies, regret rule, promotion, feasibility -> thresholds.json, primary_choice.json
         freeze         config hash, code hash, artefact hashes                    -> freeze.json (opens the test split)
         (Stages 2-5 on test)
         confirm        RQ1/RQ2(/RQ2o) with Holm, RQ3-RQ6, sensitivity            -> test_report.json / .txt

Run it offline with python study.py selftest (8 + 12 CVEs, about 7 s) or python study.py selftest --full (all 79 CVEs, about 25 s). Nine synthetic models, a mock Vul4J, no network.

4. Config refusal conditions

hp/study_config.load lists every problem and refuses: missing keys (no silent defaults); any TO_PIN_AT_FREEZE in live mode; a real provider in synthetic mode, a synthetic provider or the mock Vul4J in live mode; roles, families, tiers that differ from the design; per-provider pin rules; open-weight checksum, precision, stack and context; temperature ≤ 0 or top-p outside (0, 1]; an omitted sampling parameter without a deviation note; trials ≠ 3 or a gate other than 2-of-3; more than 4 attempts; fewer than 2,000 / 10,000 draws in live mode; extension.enabled not set explicitly; an unknown rq2o_mode; a changed split file; missing prompt slots; open models in Experiment B; an unknown suite scope; in live mode, a model without a non-empty identity_terms list (the leak scan needs it); a freeze block whose config, code (the running hp/ package and study.py), artefact or advisory hashes no longer match. freeze itself refuses once the test split holds generation, twin, input or review rows. Every value the specification marks as a default carries a // [default ...] comment, checked by a test.

5. Provisional items (reconcile with the v1.3 text)

  1. suite_unstable (§7 step 6): an incomplete run or an empty ordinary-test set.
  2. Which values are [default]: taken from v1.0 §6 plus the extension flags.
  3. fixed_sequence: RQ2o tested after RQ2, adjusted p = max(adjusted p of RQ2, p of RQ2o).
  4. RQ2o test margins: the RQ2 margins.
  5. Feasibility simulation (§15.6): regret_draws resamples of development clusters up to the test cluster count.
  6. RQ6 = Δ6.
  7. Fixed model-ID order for ties: ASCII order of model references.
  8. Policy pools: r*, Generator-aware and Exclusion over the six core reviewers.
  9. Exclusion regret: the replacement for the generator in fam(r*), on overall U.
  10. Logit scale: empirical logit with ε = 1/(2N).
  11. Indeterminate-adjacent CVEs (§15.5 item 7): any indeterminate core attempt.
  12. RQ3 strata: terciles on the analysed split; weakness class = advisory CWE.
  13. Experiment B subset: 12 seeded development CVEs among those with a core pair.
  14. Failure signature: (exception type, normalised message, first frame in the PoV test class).
  15. Cost: summed over every attempt of a call.
  16. A call closes on ok, on 4 attempts, or on a non-retryable status; resumes never re-roll a closed call.
  17. A review input that trips the leak scan excludes the pair (status leak), like an overflow.
  18. inputs.jsonl is logged in addition to the Q18 logs (it records overflow and leak exclusions).
  19. Strong panel (RQ3, descriptive): each member at its own threshold; cheap panel at t_p; open panel at t_o.
  20. Discrimination: a trial is valid if its call ended ok (an abstention with a risk score counts).
  21. Completeness: analyse-dev and confirm rebuild the schedule from the logs and refuse if any scheduled call has no row or is still open.
  22. Re-freezing: allowed (and recorded in freeze_history.jsonl) until the test split holds any work; refused after.
  23. The freeze also hashes <paths.inputs>/advisories; the code hash covers the running package, not files next to the config.
  24. Leak scan identity terms are per model, in the config (identity_terms), required in live mode.
  25. Bound convention: a one-sided bound and its p-value always agree (bound beyond b ⇔ p ≤ α); a resample with an undefined value counts against the claim.
  26. Pipeline risk: a generator row is undefined if any eligible CVE with near-misses has no U under the policy; Δ6 leaves out infeasible reviewers and lists them.
  27. Stage 1 with several PoV tests: each PoV test needs its own single stable signature.
